6. DECISIONS ALREADY MADE (do not reopen without the user)

- One FastAPI process, two stores (onboard, ground). Ground is written only by delivered link messages.
- Simulator feeds the engine in-process. Tick is 60 s of simulated time; default speed is 60x (one tick per second).
- Every scenario start builds a new World: 180 days of daily trend history (clipped at mission day 0, so
  ~142 days at T0) + 48 h of prewarm at 1-minute resolution, then T0. Negative `at` events act during the prewarm.
- Rule types: THRESHOLD, BASELINE, CUMULATIVE, COMPOUND. No TREND. Compound rules may reference simple rules
  and inline predicates, not other compound rules. Compound members: all / any / none (none needs all or any).
- Readiness formula: component = 100 at `good`, 50 at the limit, linear, clamped; score = weighted mean minus
  a penalty per open alert. Weights and anchors live in config/readiness.yaml.
- The SPE rule uses the area dosimeter, so sheltering lowers personal dose but does not clear the alert.
- demo_5min sets its own speed per segment and pauses at the end; a speed passed to /sim/scenario is
  overridden by its first event. The headache branching rule is NOT in demo_5min (kept the demo timings
  stable); show it with the headache_branching scenario, or add a symptom event after a rehearsal.
- All limits are verified: false except the BMD loss rate (NASA HRP page). Do not present the others as NASA values.
- Tooling: ruff + pytest, tsc + vitest. No mypy gate, no Playwright, no generated client, no docker.
- The in-browser simulation in useLiveSocket.ts stays only as an offline fallback; with the backend up the
  UI renders backend data only.

8. CONTRACT BETWEEN BACKEND AND UI (implemented and tested)

Both sides are now Claude's, but keep this section as the reference: any change is written here first.

Run:  cd backend ; python -m uvicorn app.main:app --port 8000      (frontend: cd frontend ; npm run dev, port 5173)
Docs: http://localhost:8000/docs (OpenAPI).   CORS is open. Vite proxies /api and /ws to :8000.

Every GET takes ?node=onboard|ground (default onboard) and returns
  { node, now, as_of, age_s, ...data }
For ground, as_of/age_s give "Data as of T-Xm Ys" (age_s seconds behind onboard time).

REST, all under /api/v1:
  GET  /health                       (also /health without the prefix)
  GET  /crew                         crew[], hazards{}, phase, mission_day
  GET  /crew/{id}/summary            crew, units, readiness, alerts (open), radiation
  GET  /crew/{id}/timeseries?signal=&from=&to=&max_points=    points [[ts, value]], unit, limits[]
  GET  /crew/{id}/baselines?window=  window default 48h. {window, z_limit{value,source_ref,verified},
                                     baselines{signal: {unit, n, mean, sd, current, z, outside}}}
                                     signals: heart_rate hrv_rmssd spo2 resp_rate skin_temp bp_systolic bp_diastolic
  GET  /environment/current          environment{signal: {value, unit, limits[]}}
  GET  /environment/timeseries?signal=...                     same shape as crew timeseries
  GET  /radiation/summary            crew{}, area{}, limits{}, spe{}
  POST /radiation/shelter            {crew_id, sheltered}  headcount during an SPE
  GET  /readiness?kind=EVA|COGNITIVE|OVERALL|PHYSICAL
  GET  /alerts?state=OPEN|RAISED|ACKNOWLEDGED|IN_TREATMENT|RESOLVED&severity=
  POST /alerts/{id}/ack | /treat | /resolve | /note {text}      onboard only, no body except /note
  GET  /rules        GET /limits     limits tree, by_signal bands, signal units
  GET  /sim/status                   scenario, seed, speed, paused, now, scenarios[]
  POST /sim/scenario                 {name, seed?, speed?}  restarts the world
  POST /sim/control                  {action: pause|resume|speed, speed?}   speed 1-10000
  GET  /link/status                  delay_s, blackout, queue_down, queue_up, ground_as_of, ground_age_s
  POST /link/blackout {on}           POST /link/delay {delay_s|null}
  POST /link/recommendation          {text, checklist?, crew_id?}  ground -> crew, arrives after the delay
  GET  /link/recommendations         onboard: delivered ones; ground: sent ones with deliver_ts
  POST /observations                 list of Observation, idempotent on id (also how to post symptom_headache)

WebSocket /ws/live?node=onboard|ground, messages:
  {type: "snapshot", node, now, as_of, age_s, sim{}, link{}, ts, scenario, seed, mission_day, phase{},
   crew[], environment{}, hazards{}, readiness{}, radiation{}}
     sent on connect and about 5 times per second. This one message can drive every view.
  {type: "alert", node, alert}                  when an alert is raised, acknowledged, treated or resolved
  {type: "recommendation", node: "onboard", recommendation}   when a ground recommendation arrives

Shapes worth knowing:
  crew[i]:  {id, callsign, role, status, top_alert{id,title,severity}|null, alert_count,
             vitals{signal: value}   (includes symptom_headache),
             trends{bmd_estimate, body_mass, vo2max_proxy, sleep_night_h, exercise_adherence_pct},
             readiness{EVA, COGNITIVE, OVERALL, PHYSICAL}, eva_go}
  status / hazards[*].status:  NOMINAL | INFO | CAUTION | WARNING | EMERGENCY
  hazards: {RADIATION|ISOLATION_CONFINEMENT|DISTANCE_FROM_EARTH|GRAVITY_FIELDS|HOSTILE_CLOSED_ENV:
            {status, alert_ids[]}}   (use link status for the DISTANCE tile)
  alert:   {id, rule_id, title, crew_id|null, severity, state, raised_ts, ack_ts, resolved_ts, hazards[],
            hrp_risks[], evidence{}, rationale, action, checklist[], notes[], origin}
  evidence (simple rule): {signal, value, unit, op, limit, limit_ref, limit_verified, limit_source_ref,
            window, agg, hysteresis_hold?}.
           Compound: {signal: "compound", logic{all, any, none}, value (conditions met), limit (conditions
            needed), members[] each with the fields above + firing (+ negated: true for `none` members),
            context?{group, branch}}
