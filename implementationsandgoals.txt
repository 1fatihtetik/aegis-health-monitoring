3. KEY DECISIONS (DO NOT REOPEN WITHOUT USER)
- One FastAPI process, two stores (`onboard`, `ground`). Ground is written only by delivered `link/` messages.
- Simulator runs in-process (60s tick, 142d daily history + 48h 1-min prewarm before T0).
- Rules: `THRESHOLD`, `BASELINE` (48h window), `CUMULATIVE`, `COMPOUND` (`all`/`any`/`none`). No `TREND` rule.
- Readiness: 100 at `good`, 50 at `limit`, linear clamped, minus open-alert penalty (`config/readiness.yaml`).
- SPE rule uses area dosimeter: sheltering lowers personal dose (`event_dose_saved_mSv`) without clearing the cabin alert.
- NEW 2026-11-14 Real NASA data (Block R):
  - Fetch once at build time (`scripts/fetch_nasa_data.py`) into `data/nasa/` (checked in); replay offline. Never call DONKI/OSDR/CDAWeb/PDS/Horizons at runtime.
  - Every observation has `provenance`: NASA_MEASURED | NASA_DERIVED | SYNTHETIC_CALIBRATED | SYNTHETIC.
  - Public in-flight astronaut vitals do not exist; crew physiology stays synthetic and is labelled so. Do not claim otherwise in UI, README or pitch.
  - Inspiration4 / OSDR data: aggregate reference ranges only, never a named person's record.
  - A limit becomes `verified: true` only with a document + clause id actually read (e.g. "NASA-STD-3001 Vol 2 Rev D [V2 6004] via OCHMO TB-004").

7. API & WS QUICK REFERENCE (`/api/v1`, `?node=onboard|ground`)
- GETs return `{ node, now, as_of, age_s, ...data }`.
- Endpoints: `GET /health`, `GET /crew`, `GET /crew/{id}/summary`, `GET /crew/{id}/timeseries?signal=&from=&to=&max_points=`, `GET /crew/{id}/baselines?window=48h`, `GET /environment/current`, `GET /environment/timeseries?signal=`, `GET /radiation/summary`, `POST /radiation/shelter {crew_id, sheltered}`, `GET /readiness?kind=`, `GET /alerts?state=&severity=`, `POST /alerts/{id}/ack|/treat|/resolve|/note {text}`, `GET /rules`, `GET /limits`, `GET /sim/status`, `POST /sim/scenario {name, seed?, speed?}`, `POST /sim/control {action: pause|resume|speed, speed?}`, `GET /link/status`, `POST /link/blackout {on}`, `POST /link/delay {delay_s|null}`, `POST /link/recommendation {text, checklist?, crew_id?}`, `GET /link/recommendations`, `POST /observations [Observation]`.
- R-2 (built): signal `area_dose_rate_absorbed` (cabin, µGy/h). Every provenance source (snapshot map, timeseries, evidence) gains `dataset: {id, label, title, source_url, retrieved, terms, transform} | null`; evidence gains `basis`. Radiation summary gains `replay` (null when synthetic) and `area.dose_rate_absorbed_uGy_h`. Timeseries gain `suspect: [[from, to]]` (onboard radiation signals). `/datasets` entries gain `label`, `reference`.
- R-0 (built): `GET /datasets?node=` -> envelope + `{datasets: [{id, tier, title, source_url, retrieved, terms, transform, files[{path, sha256_ok}], sha256_ok}], replays: [{id, dataset_id, signals, active, reason}], problems: [str], signals: {signal: {provenance, dataset_id, basis}}}`. Snapshot gains `provenance` (same map). Alert `evidence` (and compound `members`) gain `provenance`, `dataset_id`. Timeseries responses gain `provenance: {provenance, dataset_id, basis, segments: [{since, provenance, dataset_id, basis}]}`. Observation accepts `provenance` (default SYNTHETIC) + `dataset_id` (required for NASA_*; else 422).
- R-4 (built): link status + WS `link` gain `delay_source: {delay_s, provenance, dataset_id, basis, date, dataset}`; snapshot `phase.comm_delay_s` is the live delay and `phase.comm_delay_source` the same object.
- R-5 (built): `GET /spaceweather/event?node=` -> envelope + `event: {available, event_date, title, provenance, sep[], flares[], cmes[], flux: {label, unit, points[[utc, pfu|null]], suspect[], peak_pfu, peak_utc, peak_level}, s_scale[{level, ref, value, source_ref, verified}], sources{sep,events,flux: dataset meta}, problems[], primary{sep, flare, cme}}`. `POST /spaceweather/forward {crew_id?}` -> recommendation payload (same as `POST /link/recommendation`); 409 if no record is available.
- WS `/ws/live?node=onboard|ground`: `{type: "snapshot", ...}` (~5/s), `{type: "alert", node, alert}`, `{type: "recommendation", node: "onboard", recommendation}`.
